PART 3 — API TEST FLOW
================================================================================

Use Postman, Insomnia, or curl.
All requests go to: http://localhost:8080

For all protected endpoints, add this header after login:
  Key   : Authorization
  Value : Bearer <your_token_here>

Replace <your_token_here> with the actual JWT received from the login response.

SECTION C — MAINTENANCE WORKFLOW
================================================================================

Use MAINTENANCE_TOKEN or ADMIN_TOKEN for these requests.

--- C1: Create a maintenance record (vehicle auto-becomes UNDER_MAINTENANCE) ---

  Method  : POST
  URL     : http://localhost:8080/api/maintenance
  Headers :
    Content-Type: application/json
    Authorization: Bearer <MAINTENANCE_TOKEN>
  Body    :
    {
      "vehicleId": 1,
      "maintenanceType": "PREVENTIVE",
      "description": "Regular engine check and oil change",
      "scheduledDate": "2026-09-25",
      "completedDate": null,
      "status": "SCHEDULED",
      "cost": 5000.0
    }

  Expected Response (200):
    {
      "id": 1,
      "vehicleId": 1,
      "maintenanceType": "PREVENTIVE",
      ...
      "status": "SCHEDULED",
      "cost": 5000.0
    }

  SIDE EFFECT: Vehicle 1 status is now automatically set to UNDER_MAINTENANCE.
  Verify by calling GET http://localhost:8080/api/vehicles/1 → status = "UNDER_MAINTENANCE"

--- C2: Try to create a trip on a vehicle that is UNDER_MAINTENANCE ---

  Method  : POST
  URL     : http://localhost:8080/api/trips
  Headers : Authorization: Bearer <DISPATCHER_TOKEN>
  Body    :
    {
      "vehicleId": 1,
      "driverId": 101,
      "source": "Vijayawada",
      "destination": "Hyderabad"
    }

  Expected Response (400):
    "Cannot assign trip: vehicle is UNDER_MAINTENANCE"

--- C3: Complete the maintenance (vehicle auto-becomes AVAILABLE) ---

  Method  : PUT
  URL     : http://localhost:8080/api/maintenance/1/complete
  Headers : Authorization: Bearer <MAINTENANCE_TOKEN>

  Expected Response (200):
    {
      "id": 1,
      ...
      "status": "COMPLETED",
      "completedDate": "2026-09-21"   ← today's date auto-set
    }

  SIDE EFFECT: Vehicle 1 status is now automatically set back to AVAILABLE.
  Verify by calling GET http://localhost:8080/api/vehicles/1 → status = "AVAILABLE"

--- C4: Create a second maintenance record on vehicle 2 ---

  Method  : POST
  URL     : http://localhost:8080/api/maintenance

      "vehicleId": 2,

      "status": "SCHEDULED",

  Vehicle 2 will now be UNDER_MAINTENANCE.

--- C5: Complete vehicle 2 maintenance ---

  Method  : PUT
  URL     : http://localhost:8080/api/maintenance/2/complete
  Headers : Authorization: Bearer <MAINTENANCE_TOKEN>

  Vehicle 2 returns to AVAILABLE.

--- C6: Get maintenance history for vehicle 1 ---

      "destination": "Hyderabad",

--- D2: Start the trip (vehicle becomes ON_TRIP) ---

  Method  : PUT
  URL     : http://localhost:8080/api/trips/1/start
  Headers : Authorization: Bearer <DISPATCHER_TOKEN>

  Expected Response (200):
    {
      "id": 1,
      "status": "IN_PROGRESS"
    }

  SIDE EFFECT: Vehicle 1 status is now ON_TRIP.
  Verify: GET http://localhost:8080/api/vehicles/1 → status = "ON_TRIP"

--- D3: Try to assign another trip to the same vehicle (should fail) ---

  Method  : POST
  URL     : http://localhost:8080/api/trips
  Headers : Authorization: Bearer <DISPATCHER_TOKEN>
  Body    :
    {
      "vehicleId": 1,
      "driverId": 102,
      "source": "Hyderabad",
      "destination": "Chennai"
    }

  Expected Response (400):
    "Cannot assign trip: vehicle is already ON_TRIP"

--- D4: Try to schedule maintenance on an ON_TRIP vehicle (should fail) ---

  Method  : POST
  URL     : http://localhost:8080/api/maintenance
  Headers : Authorization: Bearer <MAINTENANCE_TOKEN>
  Body    :
    {
      "vehicleId": 1,
      "maintenanceType": "PREVENTIVE",
      "description": "Test",
      "scheduledDate": "2026-09-27",
      "status": "SCHEDULED",
      "cost": 1000.0
    }

  Expected Response (400):
    "Cannot schedule maintenance: vehicle is currently ON_TRIP"

--- D5: Complete the trip (vehicle returns to AVAILABLE) ---

  Method  : PUT
  URL     : http://localhost:8080/api/trips/1/complete
  Headers : Authorization: Bearer <DISPATCHER_TOKEN>

  Expected Response (200):
    {
      "id": 1,
      "status": "COMPLETED"
    }

  SIDE EFFECT: Vehicle 1 status is back to AVAILABLE.
  Verify: GET http://localhost:8080/api/vehicles/1 → status = "AVAILABLE"

--- D6: Create and cancel a trip ---

  Step 1 — Create:
    POST http://localhost:8080/api/trips
    Body: { "vehicleId": 2, "driverId": 103, "source": "Chennai", "destination": "Bangalore" }
    → Response: trip id=2, status=ASSIGNED

  Step 2 — Start:
    PUT http://localhost:8080/api/trips/2/start
    → status=IN_PROGRESS, vehicle 2 becomes ON_TRIP

  Step 3 — Cancel:
    PUT http://localhost:8080/api/trips/2/cancel
    → status=CANCELLED, vehicle 2 returns to AVAILABLE

  Step 4 — Verify:
    GET http://localhost:8080/api/vehicles/2 → status = "AVAILABLE"

PART 6 — COMMON ERRORS & FIXES
================================================================================

PROBLEM : 401 on all requests including /api/auth/login
FIX     : Check that api-gateway is started LAST. If Gateway starts before
          auth-service registers with Eureka, routes may not resolve.
          Restart Gateway after all services are UP in Eureka.

PROBLEM : 503 Service Unavailable from Gateway
FIX     : The target service (vehicle-service, trip-service, etc.) is not
          registered with Eureka. Check Eureka dashboard → all services must
          show UP status. Wait ~30 seconds after service start before testing.

PROBLEM : Feign call fails with connection refused
FIX     : Vehicle Service must be running when you call maintenance or trip
          endpoints. The Feign client calls vehicle-service via Eureka.

PROBLEM : JWT token expired (401 after 1 hour)
FIX     : Call POST /api/auth/login again to get a fresh token.

PROBLEM : 403 Forbidden even with correct role
FIX     : Make sure you registered the user with the correct role value:
          "ADMIN", "DISPATCHER", or "MAINTENANCE" (case-sensitive).

PROBLEM : Maintenance POST returns 400 "Vehicle is already under maintenance"
FIX     : The vehicle's status is already UNDER_MAINTENANCE. Either complete
          the existing maintenance first, or choose a different vehicle.

PROBLEM : Trip POST returns 400 "vehicle is already ON_TRIP"
FIX     : The vehicle is currently on another trip. Complete or cancel that
          trip first.
